Use this folder for durable reference about how the system is shaped to deliver approved product behavior.

## Key concepts

Store things like:

- architecture notes
- subsystem boundaries
- data flow and integration contracts
- technical constraints that outlive one task
- internal implementation terminology

## Standard

Do not use this folder for temporary plans or routine task notes.

If a note is mainly about what the product must do, it belongs in `../product/` instead.
