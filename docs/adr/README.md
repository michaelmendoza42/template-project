# Architecture Decision Records
Last edited: 2026-04-30

Use this folder for architecture decisions that are stable enough to rely on.

## Naming

Create files like:

- `ADR-0001-short-title.md`
- `ADR-0002-short-title.md`

## When to write an ADR

Write an ADR when a decision affects:

- system structure
- integration boundaries
- storage or API contracts
- security or safety posture
- migration direction
- long-lived technical constraints

## What does not belong here

Do not use ADRs for:

- one-off task notes
- speculative future ideas
- temporary debugging context
- draft plans that may disappear next week
